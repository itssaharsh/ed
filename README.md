# AI comedy Shorts pipeline

Fully automated, $0, fully AI-generated vertical comedy videos. Writes the joke, picks the best
one, performs it, generates every frame, cuts it to the beat, checks its own work, and uploads.

The previous version of this pipeline is preserved in [`ed/`](ed/) as a reference. This is a
rebuild, not a patch — see [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for what was wrong with it
and why each piece changed.

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
export GEMINI_API_KEY="..."             # the one required key
.venv/bin/python run.py --doctor        # what can this machine actually do?
.venv/bin/python run.py --dry-run       # build a video, upload nothing
```

`--doctor` makes one cheap live call per provider and reports exactly what will run, what will
fall back, and what is missing — in seconds, rather than finding out four minutes into a render.

No `ffmpeg` install, no `sudo` — `imageio-ffmpeg` ships a static binary.

---

## What it does

```
ideate 12 premises  →  pairwise tournament  →  script in beats  →  6 alt punchlines → tournament
   →  vocal direction + designed silences  →  speech (Orpheus)  →  shot list bound to beats
   →  generate every image  →  camera moves  →  karaoke captions  →  quality gate  →  upload
```

Roughly 14 LLM calls and 10 generated images per video. Around 4–7 minutes of wall clock.

## The three things that were broken, and what fixed them

**"bad script / bad humour."** Comedy is now generated by volume and chosen by comparison. Twelve
premises are written, then a pairwise Swiss tournament picks one; six alternative punchlines are
written, and another tournament picks the ending. The judge is never asked to score a joke out of
ten — in the research that underpins this, absolute humour scoring collapsed, with 88.5% of scores
coming out identical, while pairwise comparison reached cross-judge agreement of τ=0.889.

**"bad voice."** Speech goes through Orpheus, which takes bracketed direction (`[deadpan]`,
`[sarcastic]`) and inline non-verbals (`<sigh>`). Each line is synthesised separately and the
silences between beats are *designed* — a punchline gets a 400–650ms pre-beat, the hook gets zero.
The old pipeline sent one string to edge-tts at a flat `+18%` and replaced its own `[PAUSE]` marker
with a full stop.

**"stock footage badly fitted."** There is no stock footage. Every frame is generated for a
specific line, under a per-video style contract that keeps ten separately-generated images looking
like one production, with real camera moves over them.

## Writing the comedy by hand (no API key needed)

A **brief** supplies stages 1–6 directly — premise, script, delivery direction, shot list — so the
pipeline renders without any LLM key. It's how you write the jokes yourself, how an assistant
hands over finished material, and what you fall back to when the daily quota is spent.

```bash
python run.py --brief briefs/fridge_baseline.json --dry-run
python batch.py                 # every brief in briefs/, one at a time
python batch.py --publish       # upload the ones that pass the gate
```

Briefs are validated strictly on load (hook and punch present, punch last, emphasis words actually
in their lines, no two adjacent shots sharing a camera move), so a malformed one fails immediately
instead of producing a subtly broken video. See [`briefs/README.md`](briefs/README.md).

**`batch.py` is serial on purpose.** Free image tiers rate-limit per IP: three parallel renders
produced one image in seven minutes and spent the rest in 429 backoff, versus one image every
60–180s when paced. Parallelism here is about five times slower.

## Guardrails

The old pipeline's worst failure is in `ed/run_logs.zip`: every LLM call 404'd, and it uploaded a
stock clip of *"person"* with a placeholder script anyway. So:

- **The gate fails closed.** Mechanical checks (duration, dimensions, loudness, shot count, word
  count, image variety) run first; then a judge compares the script against a fixed quality floor.
  If the judge is unreachable, the run does not publish.
- **Uploads default to `private`.** Publishing is opt-in via `--privacy public`.
- **Premises are remembered** in `assets/premise_store.jsonl` and deduped, so the same joke is not
  rediscovered every run.
- **One render, one channel.** The old version uploaded the identical file to two channels, which
  is a duplicate-content risk under the mass-produced content policy.

## Cost

Free, but the good paths need free API keys. Without them the pipeline still runs and degrades
visibly — see [docs/SETUP.md](docs/SETUP.md).

| | Free tier | Used per day at 6 videos |
|---|---|---|
| Gemini `gemini-2.5-flash` | 500 req/day | ~84 |
| Groq Orpheus TTS | 100 req/day | ~30 |
| Cloudflare FLUX-schnell | 10,000 neurons/day | ~4,140 |
| YouTube `videos.insert` | 10,000 units/day | 9,600 ← **the real ceiling: 6 uploads/day** |

**Throughput depends almost entirely on the image provider.** Measured on this machine:

| image provider | per image | a 4-shot video, end to end |
|---|---|---|
| Cloudflare FLUX-schnell (free key) | ~5s | ~1–2 min |
| Pollinations, no key at all | 60–180s | ~7 min |

So the free-with-no-key path works, but it is the difference between six videos in an hour and
six videos in a morning. The Cloudflare key takes about three minutes to create.

## Tuning it

The comedy is in `prompts/`, not in Python. Change one file at a time, then:

```bash
.venv/bin/python run.py --dry-run --seed 7     # reproducible
```

and read `work/<run_id>/` before letting it publish. `prompts/README.md` explains the conventions
and the two rules that must hold (judge by comparison, never by score; judges do not get the
comedian persona).

## Testing

```bash
.venv/bin/python tests/test_units.py         # pure logic, no keys, instant
.venv/bin/python tests/run_offline.py        # whole pipeline, stubbed LLM, no keys
.venv/bin/python tests/validate_prompts.py   # needs a key; ~6 calls
```

`run_offline.py` exercises the render path, timing, captions and gate with no API key at all.

`validate_prompts.py` is the one that catches prompt regressions. The stub always returns
perfectly-shaped JSON, so it **cannot** detect a prompt that a real model answers in the wrong
shape. Run it once after adding your key, and again after editing any prompt file.
